# DS-ACK V3.2.2-susfs2

KernelSU Next discovery and module-startup fixes for the Exynos Galaxy S9,
S9+ and Note9. Includes all six international/Korean variants and SUSFS 2.2.0.

## Downloads

- **EROFS Enforcing:** recommended for the tested Un1ca One UI 8 setup.
- **EROFS Permissive:** alternate SELinux mode; cannot switch to Enforcing at runtime.
- **Un1ca daemon compatibility module v1.1:** install in KernelSU Next Manager
  and reboot to prevent the ROM's bundled UAPI 4 daemon overwriting UAPI 5.

These EROFS ZIPs require EROFS system/vendor/odm partitions. They preserve the
installed ROM ramdisk. Do not flash them over an ext4 ROM such as the NobleROM
test setup. SHA-256 files accompany the downloads.

## Fixed

- Native Linux 4.9 file-I/O compatibility in KernelSU's package, APK certificate,
  allowlist and module-rc readers, restoring reliable Manager discovery.
- Driver/Manager interface mismatch: official legacy driver pinned to UAPI 5,
  compatible with released Manager v3.4.2. Driver reports 33314 / v3.4.0-legacy;
  there is no official v3.4.2-legacy tag.
- Duplicate root supercall/setuid processing and the old hardcoded SELinux domain.
- Permissive handling from boot and selectable EROFS DT fstab entries.
- Un1ca daemon overwrite workaround, including installer-normalized permissions
  and repeated startup events. No authentication or SELinux enforcement bypass.

## Tested and limitations

SM-G960F: the preceding test build boots NobleROM 5.2 with Manager/SUSFS
discovery, and Un1ca Android 16 / One UI 8 with SELinux Enforcing. On Un1ca,
both daemon paths use 3.4.2/UAPI 5 and SUSFS service/boot-completed stages run
automatically after reboot with the compatibility module.

The new release builds require their own device retest. The other five models,
Permissive variant and third-party module compatibility are not device-validated.
SUSFS feature availability does not automatically enable every hiding rule.

Back up Boot/DTBO in recovery before flashing. Use the official KernelSU Next
v3.4.2 Manager and install the SUSFS userspace module separately.

## Building

EROFS is now the build default. Release mode retains incremental outputs, uses
ccache when installed, seeds independent variant outputs from completed builds,
and caches ThinLTO work while limiting concurrent linker threads. Optimisation
and debug configuration are retained; no runtime feature was removed for speed.
